# wcaf verify-evidence

## Purpose
`wcaf verify-evidence` performs **full external verification** of a WINDI evidence package:

1. PDF signature verification (authenticity of the report)
2. WCAF chain integrity verification (tamper detection)
3. Merkle log lookup (public presence)
4. STH signature verification (non-repudiation by log operator)
5. Inclusion proof verification (compact CT-style proof)

This command is designed for:
- auditors
- banks / compliance teams
- dispute resolution
- courts / regulators

---

## Command

### Basic usage
```bash
wcaf verify-evidence bundle.json report.pdf report.sig audit-key.pem
```

### Custom Merkle Log URL
```bash
wcaf verify-evidence bundle.json report.pdf report.sig audit-key.pem \
  --merkle-url=http://localhost:4051
```

### Strict mode (with consistency proof + pinning)
```bash
wcaf verify-evidence bundle.json report.pdf report.sig audit-key.pem \
  --strict --pin-file=~/.wcaf/sth-pin.json
```

### Recommended environment
- Use HTTPS merkle log endpoint in production
- Pin STHs in strict mode (Phase 3B.2)

---

## Inputs

### `bundle.json`
A WCAF bundle containing (minimum):
- `document_id`
- `timeline[]` (WCAF events)
- `combined_root_hash` (or enough fields to compute it deterministically)

### `report.pdf`
Human-readable audit report generated by windi-audit-report

### `report.sig`
Base64 signature of the PDF bytes

### `audit-key.pem`
Public key for verifying the PDF signature (RSA public key PEM for RSA-SHA256)

---

## Output

The tool prints a step-by-step verification report and finishes with:
```
✅ EVIDENCE VERIFIED
```
or
```
❌ VERIFICATION FAILED
```
with a step-specific error.

---

## Exit Codes

| Exit code | Meaning |
|-----------|---------|
| 0 | Verification OK |
| 1 | CLI usage error (missing args, invalid flags) |
| 2 | PDF signature invalid |
| 3 | Bundle chain integrity failed |
| 4 | Merkle log lookup failed (hash not found / network error) |
| 5 | STH signature invalid |
| 6 | Inclusion proof invalid |
| 7 | Consistency proof / pinning failure (Phase 3B.2+) |

**Note:** exit codes are stable API for automation pipelines.

## Verification Steps (Normative)

### Step 1 — PDF Signature
- **Algorithm:** RSA-SHA256
- **Input:** raw PDF bytes + signature (base64) + public key (PEM)
- **Output:** valid/invalid
- **Failure means:**
  - report is not authentic, or
  - report was modified after signing

### Step 2 — Bundle Chain Integrity
- Verify WCAF chain from `prev_hash → event_hash` across timeline events
- Ensure no tampering or missing events
- Ensure computed head matches expected bundle head (if present)
- **Failure means:**
  - bundle has been modified, truncated, or forged

### Step 3 — Merkle Log Lookup
- Determine `combined_root_hash` from bundle
- Query:
  ```
  GET /lookup?combined_root_hash=<hash>
  ```
- Must return `found=true` and `leaf_index`
- **Failure means:**
  - anchor was not published publicly, or
  - wrong hash, or
  - log endpoint unavailable

### Step 4 — STH Signature Verification
- Fetch current STH (or STH referenced by `/verify/:hash` bundle):
  ```
  GET /sth or returned STH
  ```
- Fetch log public key:
  ```
  GET /pubkey
  ```
- Verify Ed25519 signature over canonical JSON `{tree_size, timestamp, root_hash}`
- **Failure means:**
  - log operator signature invalid, or
  - wrong public key / key_id mismatch

### Step 5 — Inclusion Proof Verification
- Fetch inclusion proof:
  ```
  GET /proof/inclusion?leaf_index=&tree_size=
  ```
  or `/verify/:hash` response
- Recompute leaf hash using canonical JSON leaf payload:
  ```
  leaf_hash = SHA256(0x00 || canonical_json(leaf_payload))
  ```
- Recompute root using audit path and leaf position
- Compare with `sth.root_hash`
- **Failure means:**
  - anchor is not actually included in the committed tree, or
  - proof/log tampering

### Step 6 — Consistency Proof (Strict Mode Only)
- Load pinned STH from `--pin-file`
- Require `new_sth.tree_size >= pinned.tree_size`
- Fetch consistency proof:
  ```
  GET /proof/consistency?old_size=<pinned>&new_size=<current>
  ```
- Verify consistency proof
- Update pin file only if verification passes
- **Failure means:**
  - log rollback detected, or
  - split-view attack, or
  - log operator misbehavior

## Evidence Bundle Format (Recommended)

For best interoperability, create an "Evidence Pack" (Phase 3B.2) as:

```
evidence-pack.zip
  bundle.json
  report.pdf
  report.sig
  merkle-proof.json
  pubkeys/
    audit_pub.pem
    merkle_log_pub.pem
```

### `merkle-proof.json` (recommended)
```json
{
  "combined_root_hash": "<hex>",
  "leaf_index": 42,
  "leaf_payload": { ... },
  "sth": {
    "tree_size": 12345,
    "timestamp": "ISO-8601",
    "root_hash": "<hex>",
    "signature_alg": "Ed25519",
    "signature": "<base64>",
    "key_id": "hub-log-2026"
  },
  "inclusion_proof": {
    "leaf_index": 42,
    "tree_size": 12345,
    "audit_path": ["<hex>", "..."]
  }
}
```

When present, the CLI may skip network calls and verify offline.

---

## Flags

### `--merkle-url=<url>`
Base URL of the Merkle log service (default: `$MERKLE_LOG_URL` or `http://localhost:4051`).

### `--strict`
Enables pinning + consistency proof verification. Requires `--pin-file`.

### `--pin-file=<path>`
Specifies STH cache storage location (default: `~/.wcaf/sth-pin.json`).

### `--offline`
Requires `merkle-proof.json` in the evidence pack and skips network calls.

---

## Security Notes

- Always verify PDF signature before trusting any textual statements in the report.
- Always verify WCAF chain before trusting `combined_root_hash`.
- In production, require HTTPS to Merkle log endpoint.
- Use strict mode (pinning + consistency) to mitigate split-view/rollback attacks.

---

## Compliance Statement (Suggested)

If all steps pass, the verifier can state:

> The audit report is authentic (signed), the WCAF evidence chain is intact, and the evidence anchor is publicly committed in a CT-style Merkle transparency log by a signed tree head. Therefore, the document evidence existed at or before the transparency log timestamp and has not been modified since anchoring.

## Pin File Format

`~/.wcaf/sth-pin.json`:
```json
{
  "key_id": "hub-log-2026",
  "tree_size": 12345,
  "root_hash": "<hex>",
  "timestamp": "2026-02-08T14:30:00Z",
  "pinned_at": "2026-02-08T15:00:00Z"
}
```

The pin file is updated only after successful consistency proof verification.

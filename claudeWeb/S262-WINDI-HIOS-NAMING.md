# §262 · WINDI-HIOS — Hybrid Intelligence Operating System

> **"Not an AI tool. An operating layer where hybrid intelligence can act
> without losing accountability."**
>
> — Liga IA+H, 14 Mai 2026

---

## 1. O Nome

**WINDI-HIOS** = Hybrid Intelligence Operating System
**WINDI-HIOS** = Betriebssystem für hybride Intelligenzsysteme
**WINDI-HIOS** = Sistema Operacional de Inteligência Híbrida

Não é renomeação do WINDI. É **promoção a categoria**: o ecossistema deixa
de ser "colecção de produtos governados" e passa a ser **infraestrutura
constitucional para inteligência híbrida**.

O nome existente *WINDI* persiste como **organização e marca-mãe**.
*HIOS* nomeia o que a organização **constrói**: o sistema operacional que
permite humanos e agentes coordenarem-se sob admissibilidade verificável.

---

## 2. Definição Operacional

WINDI-HIOS **não é** um sistema operativo para computadores.

WINDI-HIOS **é** uma camada operacional para coordenar:

- humanos
- agentes (LLMs, MCPs, scripts)
- ferramentas (APIs, services, módulos)
- memória (sessões, lineage, snapshots)
- decisões (admissibilidade, autorização, selagem)
- provas (receipts, hashes, verify URLs)

…dentro de **limites verificáveis**.

A unidade fundamental não é o processo. É a **acção admissível**.

```

```

### 3.1. Human Workstation Layer

A superfície diária do operador humano. Inbox de tarefas, documentos,
agentes disponíveis, decisões pendentes, receipts, calendário operacional,
estado dos projectos, alertas de admissibilidade, painel *"o que requer
decisão humana"*.

Encarnação actual: A4Desk renascido + GEN7 Desktop UI + Dragon Palette.

### 3.2. Agent Runtime Layer

Onde os agentes vivem com identidade soberana. Cada agente tem DID, função,
permissões, escopo, memória permitida, endpoints autorizados, logs obrigatórios.

Estados possíveis: `active` / `sleeping` / `observing` / `waiting_human` /
`blocked_governance` / `retired`.

Encarnação actual: Three Dragons (Guardian, Architect, Witness, Construtor)
+ W-Certification (onboarding) + W-LAB-001 (cinco mini-jogos cognitivos).

### 3.3. Tool & Endpoint Layer

Ferramentas conectáveis sob regra constitucional: *"Nenhuma ferramenta crítica
executa sem identidade, escopo e receipt."*

Encarnação actual: W-SITES-001 (:8192), W-LEXICON-001, W-VERIFY (v2 + Modus4),
CSS Guardian + Generation Grammar, W-MAIL (pending), W-CORTEX (futuro),
document generators, payment bridge (soberano), compliance checker, external APIs.

### 3.4. Governance Kernel — O Coração

**Não é UI. Não é agente. Não é workflow.** É o kernel constitucional.

Responde, antes de qualquer execução:

- Isto pode executar?
- Quem autorizou?
- Qual regra aplica?
- Há prova suficiente?
- Isto altera estado?
- Precisa de I9 humano?
- Gera receipt?
- Bloqueia?

Encarnação actual: Constitutional Gate · I9 Human Decision Gate · I11 Ledger ·
I14 Verifiability · T7 Adversarial Protocol · §261 Bind-time Admissibility ·
Chain Integrity · Policy-as-Code (futuro: REGO).

**Frase técnica canónica:** *"Antes de agir, o sistema pergunta ao kernel se
a acção é admissível."*

### 3.5. Cognitive Continuity Layer

A camada que impede o sistema de **esquecer o caminho**.

Funções:
- preservar contexto entre sessões
- registar decisões e seu raciocínio
- manter lineage (supersedes/superseded_by)
- guardar snapshots reversíveis
- distinguir memória, evidência e opinião
- evitar deriva semântica

Encarnação actual: §236 (CLAUDE.md + CLAUDE-HISTORY.md) · §261 (Cognitive
Bind Packet) · Memory Loop (osmose → candidates → seal) · W-CAP (.wcap format)
· **PingPong Protocol (§263)**.

### 3.6. Proof & Ledger Layer

Tudo o que importa deixa rastro.

Funções: receipts · hashes SHA-256 · timestamps · actor DID · document lineage
· supersedes/superseded_by · withdrawal receipts · verification URLs ·
public/private proof split.

Encarnação actual: Forensic Ledger :8101 · Verify Public · JMPG (constitutional
PDF stamps) · §152 W-DRAGON-001 Forensic-Ready.

**Sem esta camada, o sistema é apenas automação. Com ela, é infraestrutura
verificável.**

### 3.7. Application Surface Layer

Os produtos que nascem em cima. **Não são o kernel.** São aplicações de
referência que demonstram que o kernel funciona.

Encarnação actual: W-SITES-001 (commercial) · W-ENTERPRISE-001 + VERA
(institutional compliance) · W-LAW-001 (legal governance) · W-TRAVEL-001
(audio guide DAB+/Galileo, blueprint) · W-MAIL (pending) · W-SOCIAL-001
(reserved) · Foundation Portals (IDENTITY, MEMORY, VERIFY, ENTERPRISE).

## 4. Two-Track Foundation Aplicada à Arquitectura

§248 Lei V projecta-se nas 7 camadas:

| Track | Camadas | Modelo |
|-------|---------|--------|
| **Civic / Free** | Governance Kernel · Cognitive Continuity · Proof & Ledger | Kernel intocável, sem monetização |
| **Institutional / Paid** | Application Surface (W-ENTERPRISE, W-LAW, W-TRAVEL, W-MAIL) | Receita aqui, não no Kernel |
| **Compartilhado** | Human Workstation · Agent Runtime · Tool & Endpoint | Acesso modulado por DID + tier |

**Princípio constitucional inviolável:** monetização **nunca** toca o Kernel.

Quem paga, paga pela superfície aplicacional. O chão constitucional é
património civil.

## 6. Primeira Pedra — WINDI-HIOS v0.1

> **Minimum Constitutional Runtime**

A pedra fundamental não é nem UI, nem agentes, nem orquestração LLM.

É **o mecanismo formal que impede inteligências híbridas de perderem o
chão enquanto raciocinam longitudinalmente**.

Componentes mínimos do v0.1:

1. **CBP como objecto JSON** (não markdown solto)
   — schema canónico, hashable, validável, versionado.

2. **Admissibility Gate como serviço** (não interpretação humana)
   — MCP tool ou gateway proxy; pré-condição de execução constitucional.

3. **Cognitive Drift Monitor** com 3 métricas mínimas:
   - densidade estrutural por turno
   - frequência de padrões hiperdefensivos ("mas antes de…", N objecções)
   - distância semântica missão-declarada ↔ output-do-turno

**Schema técnico e implementação ficam para sprint dedicado.**

Este selo aprova **direcção**, não **design**.

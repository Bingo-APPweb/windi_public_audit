📋 1. Abstract

This document specifies the .jmpg Continuum protocol: a portable, self-contained binary format for sovereign video distribution. The .jmpg object encapsulates:

  • A playable onboard segment (30 seconds of video)
  • A cryptographically signed streaming manifest

Within a single file. This design ensures:

  • Instant playback without network dependency
  • Seamless transition to full-length streaming from the creator's sovereign Vault
  • Verifiable content integrity via SHA-256 sealing
  • Distribution through any channel capable of transmitting a binary file

🐉 Core Definition

A .jmpg is not a file format. It is a sovereignty assertion wrapped in a playable container.

The protocol is designed to be codec-agnostic, transport-agnostic, and platform-agnostic, operating on the principle that video distribution should not require permission from any intermediary.

⚖️ 2. Design Principles

The .jmpg protocol is governed by seven invariant design principles that cannot be violated by any implementation.

P1 — OFFLINE-FIRST
The File IS the Experience
The onboard segment must be fully playable without any network connection. The file itself is the experience.
P2 — INSTANT START
< 200ms to Play
Playback must begin within 200ms of file access. No buffering wheel. No loading screen. No negotiation.
P3 — CREATOR SOVEREIGNTY
Vault-Only Streaming
The streaming manifest points exclusively to the creator's Vault. No intermediary may intercept without explicit cryptographic authorization.
P4 — VERIFIABLE INTEGRITY
SHA-256 + Ledger
Every .jmpg includes a SHA-256 seal of both onboard and manifest, registered in the WINDI Forensic Ledger. Any tampering is detectable.
P5 — TRANSPORT AGNOSTICISM
Any Binary Channel
Transmissible via WhatsApp, Telegram, email, HTTP, QR code, Bluetooth, NFC, USB, or any medium that can carry a binary payload.
P6 — CODEC FLEXIBILITY
Negotiate, Don't Mandate
Supports any video codec (H.264 baseline for compatibility, H.265/AV1 for efficiency). The manifest declares; the player negotiates.
P7 — PROGRESSIVE SOVEREIGNTY
Tiered Access
Supports FREE onboard / subscriber-only stream without platform authentication. Tier detection embedded in manifest, resolved by Vault.

⚙️ 4. The JMPG Trigger: Packaging Pipeline

The JMPG Trigger transforms a raw video upload into a distributable .jmpg object. It runs entirely locally on the creator's Vault, consuming zero external API calls and incurring zero variable cost.

4.1 Pipeline Stages

1

INGEST

Creator uploads video (MP4, MOV, MKV, WebM). Trigger validates file, extracts metadata (duration, resolution, codec), creates content_id (UUIDv7).

2

TRANSCODE ONBOARD

ffmpeg extracts first 30s → H.264 Baseline 720p/1200kbps + AAC 128kbps. MP4 with moov atom at front (faststart) for instant playback.

3

TRANSCODE STREAM

ffmpeg generates adaptive HLS: 1080p/4500kbps (H.265), 720p/2000kbps, 480p/800kbps, 360p/400kbps. 6-second segments, GZIP manifests.

4

GENERATE MANIFEST

Construct streaming manifest JSON with vault_endpoint, content_path, adaptive_profiles, continuity timing. Sign with creator's Ed25519 key.

5

ASSEMBLE BINARY

Concatenate MAGIC + VERSION + FLAGS + HEADER + ONBOARD + MANIFEST. Compute SHA-256 seal over combined payload. Append as final 64 bytes.

6

REGISTER IN LEDGER

Write content_id, seal hash, creator DID, timestamp to WINDI Forensic Ledger (SQLite + SHA-256 chain). Immutable record of authorship.

4.2 Processing Performance

All processing runs on a standard VPS (2 vCPU, 4GB RAM — the €4/month Strato instance). Benchmarks for 30-minute source video:

▶️ 5. Player Architecture

The .jmpg player is a lightweight JavaScript module (< 50KB gzipped) implementing the following playback state machine.

5.1 Playback State Machine

S0
INIT
Receive binary, parse MAGIC, validate version, extract HEADER
S1
ONBOARD
Create Blob URL from ONBOARD bytes, play via <video>. <200ms. No network.
S2
HANDOFF
At (end−500ms), fetch HLS manifest from Vault. DID challenge if required.
S3
STREAMING
Crossfade to HLS stream. Adaptive bitrate. Seamless continuation.
S4
GATED
No stream access → subscription prompt after onboard. Fair gate.
S5
OFFLINE
No network → show fallback message, retry silently. Never breaks.

5.2 Verification Flow

At any point, verify integrity by computing SHA-256 over [HEADER + ONBOARD + MANIFEST] and comparing against SEAL bytes. If registered in Ledger, verification extends to provenance. Privacy by design: no personal data from viewer required.

🔐 6. Security and Governance

6.1 Content Integrity

The SHA-256 seal provides tamper detection at binary level. If any byte is modified, the seal breaks. The Forensic Ledger provides a second layer: even if an attacker replaces the entire file with a new valid seal, the Ledger retains the original hash.

6.2 Identity and Authentication

  • Creator identity: WINDI DID Cycle (Ed25519 + UUIDv7)
  • Manifest signature: Proves streaming endpoint authorized by creator's private key
  • Viewer authentication: DID Challenge protocol — Vault issues nonce, viewer signs, Vault verifies
  • No passwords. No cookies. No third-party OAuth. The DID is the identity.

6.3 Tier Detection and Access Control

The FLAGS bitfield encodes tier information:

🔍 9. WINDI.Tube: The Sovereign Discovery Layer

While .jmpg enables sovereign distribution, discovery requires an additional layer.

9.1 Architecture Principle

WINDI.Tube does not host videos. It does not store content. It does not control distribution. It indexes .jmpg metadata (title, tags, creator DID, thumbnail, governance classification) and serves as a search interface. The video always lives in the creator's Vault.

9.2 Discovery Mechanisms

  • Human Curated Feeds (Potts): Federated groups of creators curate thematic feeds. Discovery driven by human trust, not algorithmic manipulation.
  • Reputation-Based Ranking: Cryptographic proofs of authorship, cumulative publishing history, peer recommendations, institutional certifications. Reputation accrues over time and cannot be bought.
  • Semantic Search: Full-text and tag-based search across the index. Runs on metadata only; no content is ever copied.
